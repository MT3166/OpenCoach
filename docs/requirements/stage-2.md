# OpenCoach 二次开发任务 · 阶段 2 / 5

## ① 你的角色与当前工程

你是接手 **OpenCoach** 的资深全栈工程师（Django 5.2 + DRF + Vue 3 + Vite，SQLite，同镜像交付）。

本阶段建立在**阶段 1（课包有效期）已完成**的工程之上；请先通读现状，确认有效期的判定口径（`available / remaining / reserved / expired`）后再动手。

## ② 环境与硬性技术约束

同阶段 1：Python 3.12、Node ≥ 24、运行期无需 Node、尽量不新增依赖。

## ③ 本阶段需求：调课 / 改期

教练与学员都需要把一条**已有的预约改到另一节课**：

1. 学员可以把**自己的**、尚在可操作范围内（距原课次开课 ≥ 12 小时）的预约改到另一节**未开始、未取消、有剩余名额、与自己无时间冲突**的课次。
2. 教练可以**代任意学员**改期。
3. 改期必须**原子**：成功后原预约变为"已取消"、目标课次出现一条**活跃预约**，对应的**预占课时随之转移**；任一步失败则整体回滚，不留下半成品。
4. 目标课次所属课包类型必须与学员持有的课包一致（私教对私教、小班对小班）。
5. 只有当学员对目标课次仍有**可预占的有效课时**时才允许改期（**必须遵守阶段 1 的有效期规则**；过期课时不算可预占）。
6. **幂等**：同一 `operation_key` 重复提交只生效一次，返回同一结果。
7. **保留历史**：原预约以"已取消"状态保留，可追溯，不物理删除。

## ④ 不可违背的契约

遵守随附的《契约附件》。

**本阶段附加 API 契约（必须严格实现，供验收）：**

- 新增 `POST /api/v1/student/bookings/<pk>/reschedule/`，请求体 `{"session_id": <int>, "operation_key": "<uuid>"}`，响应为 `booking_data`（目标课次上的新活跃预约）。
- 新增 `POST /api/v1/coach/bookings/<pk>/reschedule/`，请求体同上（教练越权代操作）。
- 成功后断言：原 `<pk>` 预约状态为 `cancelled`，目标课次存在且仅存在一条该学员的活跃预约。
