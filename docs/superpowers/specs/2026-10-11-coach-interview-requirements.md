## 1. 采访原文

> 就是实际上自由教练需要的是，比如说可以记录他的出勤率，然后呢，他续课以及剩余多少课时这种，然后至于说训练计划的话，就是不需要有什么目标的那种安排，就是练了什么记进去，然后再去做一些课后总结就行了。

## 2. 产品目标

帮助自由教练用很短的课后操作留下真实出勤、课时与课程记录，持续掌握学员的到课情况、续课记录和剩余课时，让学员能回看自己的课程历史。

教练打开一个学员档案，应能回答：最近是否正常到课、还有多少课时、上次什么时候续课，以及上节课练了什么、教练有什么总结。日常确认出勤应无需进入档案或填写完整表单。

## 3. 从采访提取的信号

| 原话 | 可直接提取的需求 | 需要进一步定义的口径 |
| --- | --- | --- |
| 记录出勤率 | 记录每次课程的出勤结果，并提供统计 | 统计学员还是教练；统计周期、取消和未处理课程如何计算 |
| 他续课 | 记录续课情况，能查询历史 | 是记录已购买课时，还是还要管理催续课与付款；本文建议先做实际续课录入 |
| 剩余多少课时 | 显示可信的课时余额 | 沿用已有剩余、预占和可约的账目区分 |
| 不需要有什么目标的那种安排 | 记录实际训练无需先设置目标或创建计划 | 是否将既有课后作业与学员提交功能移出首版，需要用户确定 |
| 练了什么记进去 | 记录每节课的实际训练内容 | 是否需要结构化动作数据；本文建议文字即可，组数/次数/重量等可选 |
| 做一些课后总结 | 教练为本节课留下总结 | 总结是否给学员看；本文建议默认双方可见，内部备注另行定义 |

## 4. 候选功能需求与验收标准

### R1：课程出勤记录与学员出勤统计（对象待确认）

作为教练，我希望在课程结束后记录每位学员是否到课，以便查看教学服务的实际进行情况。

- 每笔个人预约可标记到课、缺席；取消保留独立状态。小班按人分别记录。
- 学员档案显示所选月份的到课次数、缺席次数、取消次数、待处理次数及出勤率。
- 点击统计能回看对应课程，避免只有百分比却无法查来源。
- 出勤结果与是否扣课分别表达：缺席免扣仍属于缺席，取消不等同于缺席。

建议的统计口径：

`出勤率 = 已确认到课次数 ÷（已确认到课次数 + 已确认缺席次数）`

- 已取消和未来课程不进入分母。
- 已过去但尚未确认出勤的课程单列「待处理」，不自动判到课或缺席。
- 分母为0时显示「暂无已确认出勤」，不显示0%或100%。
- 展示百分比时同时展示分子和分母，例如「80% · 到课8/应到10」，并展示待处理数，便于正确理解。
- 缺席消课与缺席免消课均进入缺席次数；扣课按既有账目规则执行。

验收示例：本月8次到课、2次缺席、2次取消、1次待处理，显示出勤率80%、取消2次、待处理1次。确认缺席时无论选择消课还是免消课，该次均计为缺席；沿用既有规则，已处理预约不在此新增结局改写能力。

该公式是候选规则，并非采访者已经确认的业务口径。若对象确认为教练工作量，则另定义实际上课节数/时长，不能直接套用学员出勤率。

### R2：续课录入与历史

作为教练，我希望记录学员每次实际续课，以便知道新增了多少课时，并能追溯余额来源。

- 手动录入学员、课包类型、新增课时数量；记录录入时间，并在历史中展示。
- 同一档案查看购买/续课历史及最近一次录入时间。首次购买与后续续课均保留可追溯流水。
- 录入成功后更新对应课包；私教与小班分别计算。
- 沿用现有 UUID 幂等保障，网络重试不重复增加课时。

验收示例：学员私教剩余2次，新增购买10次后剩余12次；同次请求重试仍为12次，历史只新增一笔。此处是课时录入，不代表系统验证了线下付款。

低余额名单、待续课标记、付款金额、付款状态、自动提醒和续课率分析并非本段采访已明确的需求，可后续单独确认。

### R3：学员课时余额与账目

作为教练和学员，我希望看到一致的剩余课时，方便安排后续课程和核对消课。

- 学员档案和学员自己的页面展示两类课包的剩余、预占、可约次数。
- 购买、预约、取消、完课和缺席处理后，双方看到同一服务端账目结果。
- 能查购买与消课流水，包含发生时间、次数、课包类型及关联课程。
- 「剩余课时」是尚未消耗的课时；「可约课时」还需减去当前预约预占，界面明确表达。

验收示例：剩余12次、预约预占2次时显示「剩余12、已约2、可约10」。确认一节完课后显示「剩余11、已约1、可约10」；取消另一节后显示「剩余11、已约0、可约11」。

### R4：实际训练内容记录

作为教练，我希望每次课后直接记下练过的内容，方便自己接续教学、学员回看。

- 记录关联具体学员、课程和上课日期。
- 文字即可描述实际训练，例如「深蹲、划船、核心稳定」。
- 结构化动作与组数、次数、重量、时长作为可选详细信息，不要求每节课全部填写。
- 保存记录无需先创建训练计划、设置训练目标或等待学员提交作业。
- 小班各学员记录独立，同班不能查看其他人的个人训练内容。

验收示例：教练只填写「深蹲、划船、核心稳定」即可保存该学员本节课记录；学员能在课程历史看到它。没有目标或课后任务时，保存流程同样成立。

### R5：教练课后总结

作为教练，我希望给本节课留下简短总结，方便学员回顾，也便于下次教学衔接。

- 总结附在本节课的个人记录中；为减少填写成本，建议与实际训练内容共用一个选填的文字输入，例如「今天练了深蹲和划船，注意膝盖方向」。两种信息的语义保留，首版无需分别填写两个表单。
- 可自由填写表现、需注意的动作或下次上课的建议，不要求设置量化目标。
- 建议学员可读取教练分享的总结；总结给谁看仍属于产品建议，需要确认。
- 保存后可以修正文字，不产生额外课时扣除。
- 学员无需先提交训练数据，教练就能撰写本节课总结。

验收示例：教练保存「今天动作稳定，深蹲注意膝盖方向，下次继续练习」，学员在该节课记录中看到总结；再次修正总结不会生成新的消课流水。

## 5. 推荐的日常流程

1. 教练从「记课」直接选择学员，或打开已预约课程；学员约课能力保留。
2. 上课结束后，直接记课显示学员、课包类型与日期后点击「记一节课 · 扣1次」；已有预约使用「确认完课 · 扣1次」。出勤、扣课、余额与课程历史自动同步。
3. 教练愿意补充时写一句「今天练了什么／有什么要注意」，训练内容与总结合并为一个选填输入；详细动作数据按需展开。
4. 页面立即显示「本节已完成，剩余X次」，学员能查看同一节课和账目。未填文字不影响完成出勤处理。
5. 实际发生续课时，教练从学员档案录入新增课时。出勤统计和续课历史从真实业务记录汇总，无需每日重复填报。

完课/扣课与文字记录允许分步完成。若完课已成功而选填文字保存失败，界面明确告知文字未保存并保留输入，重试只保存文字；不能再发起一笔扣课。按钮和成功反馈必须以服务端结果为准。

缺席与取消为独立入口，教练必须选择真实结果；正常完课作为主要路径，不自动把未处理课程判成到课。小班卡片逐人确认，主操作明确对应学员，不能默认把全班标到课。

## 6. 首版范围建议

推荐围绕 R1–R5 形成轻量的日常管理闭环，并保留已确认的邀请、账号、排课、约课、私教/小班和独立部署基础。

本段采访支持的简化是「记录实际训练无需先做目标计划」。据此建议把目标型计划编排、学员课后作业提交及待点评队列放到后续需求池；其中学员作业是否退出首版仍需用户决定，不能把这段采访解读为已要求删除全部指导功能。

| 范围方案 | 取舍 |
| --- | --- |
| 优先日常管理与课程记录（推荐） | 首版围绕出勤、续课、余额、实际训练与总结；课后作业另行评估，教练操作更短 |
| 完整保留旧范围并增加出勤统计 | 保留计划/提交/点评，加上经营记录，业务覆盖较广，开发和日常操作更多 |
| 将计划与作业做成每实例可选模块 | 满足不同教练，但增加开关、权限与测试组合；现阶段建议先验证统一首版范围 |

首版范围由产品负责人结合此次访谈与既有需求确认。

## 7. 与现有正式版计划的关系

- 技术架构与独立部署方向继续适用。
- 出勤结果已存在于预约状态，但出勤率、取消和待处理的汇总展示需要明确口径并新增查询/页面。
- 现有购买流水、钱包计算和幂等服务可承接续课录入；实际购买日期与录入日期是否区分需进一步确认，首版建议明确展示录入时间。
- 现有课上记录已有动作与note，未来需适配文字即可保存的流程；原动作校验要求1–50个动作，不能原样套给简化后的文字记录。
- 教练课后总结属于课程记录；既有「教练点评学员提交」是另一条流程，不能仅改界面名称就认为已满足本需求。
- 迁移计划任务2–3的首页、任务4–6的学员/课包/出勤页面、任务7–8的训练指导范围都需要按最终确认结果复核，再实施。
- 已有历史训练计划、提交与点评需保留可读，不因首版范围调整而删除数据。

## 9. 简单使用与习惯形成机制（用户方向与对象已明确，交互候选）

核心使用者为教练。日常入口围绕「记课」和「学员」组织：记课承接每次课程结束后的确认与选填记录，学员承接余额核对、历史回看及实际续课录入。用户已批准直接记课，并保留现有预约课程的快捷确认。

### H1：固定使用时机

把动作放在已有生活节奏中：每节课结束后，教练打开「今天的课」确认这一位学员的完课结果。下一次打开应用时优先显示尚未处理的课程，已处理项清楚标记。

提示仅在应用内使用实际待处理记录；未来课程、取消课程和已处理课程不制造额外任务。此处不新增短信、微信消息或固定频率催促。

### H2：一个主要动作，文字可选

- 正常完课路径：找到课程 → 点击「确认完课 · 扣1次」→ 看见真实完成状态与余额。
- 如愿意记录，填写一句话即可，允许之后补充。
- 组数、次数、重量、时长、目标和总结分类不作为日常必填项。
- 每天不再重复填写出勤百分比、剩余课时或另外的日报，均从真实记录计算。
- 网络加载时防止重复点击；重试沿用既有幂等规则。教学判断仍由教练作出。

设计目标：找到当前课程后，正常出勤确认无需填写字段，一次明确点击完成；加一句文字时的整段操作目标在30秒内。耗时是试用目标，需要实际验证。

### H3：及时看到价值

确认后立即反馈本节状态和剩余课时。再次上课时能快速回看上一节已有记录，减少回忆和核账时间；训练历史从已保存内容累积，避免额外维护第二份档案。

学员侧建议围绕「下一节课、还有几次、上节课记录」使用，不要求每天打开或为了维持连续天数打卡。

### H4：允许中断和恢复

忘记当天确认时，后续进入应用能找到待处理课程，按真实情况补确认；此时保留原课程日期，并遵守既有完课/缺席规则。没有文字记录时可后来补写，不能自动生成虚构训练内容。

文字输入在当前编辑过程中保留，已保存内容跨设备可读取；敏感信息不写到不受控的共享浏览器存储。离线写入和设备间同步草稿不属于本次需求。

### 机制取舍

| 候选机制 | 使用成本与价值 |
| --- | --- |
| 每节课后确认并得到余额反馈（推荐） | 与现有上课节奏一致，一次业务动作完成记账并积累历史 |
| 每日汇总填写或固定日打卡 | 新增单独任务，仍需回忆当天每节课，需额外验证其必要性 |
| 积分、连续天数和奖励系统 | 需要新增规则和维护，首版先验证真实业务收益能否支持持续使用 |

试用观察建议：邀请原采访教练试用一周，观察实际确认耗时、已结束课程中完成确认的比例、是否主动回看记录，以及中断后能否顺利补记。一次性演示完成全部功能不能替代持续使用验证。

## 10. 直接记课与预约快捷确认（入口已批准）

用户最新回复「OK」确认：支持直接记课，并保留预约课程的快捷确认。微信或线下安排的课也能在结束后直接记录。

### D1：最小输入与明确扣课

- 学员有档案即可由教练记课，学员尚未接受邀请不影响教练记录。
- 直接记课输入学员、课包类型、上课日期和选填文字；日期默认上海今天，允许补记过去日期，未来日期不接受完课记账。
- 只有一种课包可用时可预选该类型；两种课包可用时明确让教练选择。提交前显示学员、日期、类型及「扣1次」，无需填写课程标题、地点或精确起止时间。
- 未填写文字也能完成真实课时记录；实际训练与总结合并为一个选填框，详细动作数据按需填写。
- 保存成功后立即显示真实余额和这一节历史记录；填写和选择都发生在明确的扣课动作前。

### D2：与预约记录共存

- 对已有预约，使用原预约确认完课，沿用原课包和预占释放规则。
- 从直接入口发现该学员所选日期/类型有未处理预约时，优先展示这些预约及快捷确认，允许教练明确选择「另记一节」以记录独立发生的课程。
- 不仅凭同日、同人就自动关联或合并；同一学员同一天可实际上多节课。
- 已处理预约和直接记录出现在同一课程历史里，来源清楚；重复显示同一预约不产生新的账目。

### D3：可靠账目与低成本重试

- 直接记课与对应一次消课在同一写事务中保存。私教、小班分别计算，已有预约预占不能被另一笔直接记课占用。
- 同次保存使用唯一操作标识；重试返回已有记录，不重复消课。该标识用于不同学员、类型或日期时拒绝复用。
- 同日多节真实课程各使用新操作标识，历史保留各节记录。
- 不足以扣除一次可用课时则提示核对或录入课包，不返回成功，也不留下孤立的消课流水。
- 保存后补写/修正文字只更新记录，不再次扣课；出勤确认后的其他结局改写或冲正另作业务设计，不自动扩入本轮。

### D4：历史和统计的真实含义

直接记课保存实际上课日期；没有准确时间时不制造起止时间或时长。学员加入后能读取属于自己的历史，其他学员不可读取。

直接记课提供实际已上课次数，不能单独推导完整出勤率：只补录到课仍无法知道应到但缺席的课程数量。未确认出勤口径前，界面展示实际次数和有来源的预约出勤，不把缺少应到记录的学员显示为100%出勤。

### D5：验收案例

1. 未提前排课的学员档案有私教5次，直接记一节后剩余4次，出现一条历史和一笔消课；无需创建目标计划或注册学员账号。
2. 同次请求重试后仍剩余4次；再次编辑该节课的文字后余额保持4次。
3. 剩余2次且被2笔预约预占时，额外直接记课被拒绝；原预约确认完课正常消耗1次并释放对应预占。
4. 同日确实上了两节独立课程，分别记录后产生两条历史与两笔消课。
5. 同一笔预约无论从课程卡片还是记课入口确认，都只消耗一次；单凭同日不能把独立课程误合并。
6. 可用仅1次时并发保存两节独立课程，只有一节成功，无负余额或孤立记录。
7. 未填文字、补记过去日期均可保存；未来日期和越权请求拒绝。

直接记课入口与教练习惯目标已开发并验收，既有历史数据保留。当前展示实际次数与限定来源的预约到课率；完整跨渠道应到口径和旧课后作业后续取舍是独立的产品决策。
