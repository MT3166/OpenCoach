# OpenCoach 开发核验记录

三名只读核验探子分别检查权限与邀请、预约与课时事务、容器与部署工具。代码和最终验证由主代理负责。

## 已复核并修正

- 同一 IP 不同端口的 Cookie 冲突：根据每个实例的独立应用密钥派生 session 和 CSRF Cookie 名称。两个实例在同一浏览器中保持各自身份与表单有效性的回归测试，修正前返回 403，修正后通过。
- 科学计数法重量可能膨胀：在格式化前限制非零重量的数量级与小数精度，最多两位小数；保留 0 和 0.25 kg 增量。极端指数回归测试修正前失败，修正后通过。
- 已有部署配置不符合本测试实例契约：复用配置前核验 8001、DEBUG=0、独立密钥、允许主机、CSRF 来源和独立数据路径；不默默覆盖既有密钥。
- 更新遗留源码：记录工具此前上传的源码清单，仅删除其中被本版本移除的文件，拒绝触及 data 或 .env，保留未跟踪文件。实际临时文件系统回归验证这些副作用。
- 源码归档进入镜像：将归档及部署元数据排除出构建上下文。
- 补充真实文件库的并发重复购买、重复预约、重复完课和小班最后名额验证。

## 未采用的业务建议

“开课后必须禁止教练取消整堂课”超出了已确认规则。规格第 5.2 节允许教练取消并释放仍未消耗的课时，只在已有消课记录时禁止整堂取消。临时取消已开始但未产生消课的课程是允许的教练操作，因此保持该规则，并增加开课后取消与小班部分已消课的测试，确保不覆盖已消耗账目。

## 后续验证

所有修正通过本地测试后，部署到独立测试目录；随后验证公网真实 HTTP 操作、容器重启后的数据保留、备份恢复和手机页面。
